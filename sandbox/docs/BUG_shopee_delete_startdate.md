# Bug: Shopee delete ทับ `shopee_orderlist_start_date` เป็นเดือนล่าสุด

อัปเดต: 2026-07-14

## อาการ

กดลบจาก `2606` → คาดหวัง `DataDownload.shopee_orderlist_start_date = 2026-06-01`  
แต่ได้ `2026-07-01` (เดือนปัจจุบัน)

## สาเหตุ

PHP (`saletaxreport::del_data_platform`) วน **จากเดือนที่เลือก → เดือนปัจจุบัน**:

1. ลบ `2606` → SP ตั้ง `@start_date = 2026-06-01` ✓  
2. ลบ `2607` → SP ตั้ง `@start_date = 2026-07-01` ✗ ทับค่าเดิม

SP `delete_shopee_order_by_year_month` อัปเดต `DataDownload` **ทุกครั้งที่ถูกเรียก** ด้วยเดือนของรอบนั้น

## แนวแก้ที่แนะนำ (เลือก 1)

### A) กลับทิศลูป (ตามที่คุณเสนอ) — แก้เร็ว

วนจากเดือนปัจจุบันลงมาหาเดือนที่เลือก → รอบสุดท้ายเป็น `2606` → `start_date` ถูกต้อง

### B) ตั้ง checkpoint ครั้งเดียวหลังลบครบ — ชัดกว่า

- ลบทีละเดือนตามเดิม (หรือกลับทิศก็ได้)  
- **อย่าพึ่ง** UPDATE ใน SP เป็นตัวกำหนดค่าสุดท้าย  
- หลังลูปจบ: ตั้ง `shopee_orderlist_start_date` เป็นวันที่ 1 ของเดือนที่ผู้ใช้เลือกครั้งเดียว

### อย่าลืม

- Lazada / TikTok อาจมีแพทเทิร์นเดียวกันถ้า SP อัปเดต checkpoint เช่นกัน  
- `TRUNCATE shopee_return_order` ใน SP รันทุกเดือนที่ลบ — ควรรันครั้งเดียวก็พอ (งานถัดไป)
